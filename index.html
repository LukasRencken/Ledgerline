Open Ledgerline How it works

1 · Inbound Reconciliation

Drop receipts and a bank statement. Ledgerline matches by vendor, amount, and settlement window, then explains every suggested journal entry in plain English.

2 · Model Integrity

Snapshot your budget model. Every cell change is diffed, logged, and flagged when a material assumption moves without a note.

3 · One Audit Trail

Both modules write to the same hash-chained event log. Export a single audit package that traces any number back to its evidence.

Built on accounting principles

  • Double-entry — every accepted match posts a balanced debit and credit; reversals post the opposite.
  • Immutability — the event log is append-only, hash-chained (SHA-256), and sealed at export.
  • Materiality — anomaly thresholds are configurable per absolute and relative magnitude.
  • Local-first — your ledger never leaves this browser tab; persisted locally, exportable anytime.

Inbound Reconciliation

Paste receipts (vendor | YYYY-MM-DD | amount | tax | [currency]) and bank lines (YYYY-MM-DD | description | amount | [currency]). Amounts may include thousands separators. Currency defaults to ZAR; cross-currency pairs never match.

Model Integrity

Snapshot a budget model (JSON object of cell: value where value is string/number/null). Material changes are flagged and logged.

Anomaly Register

Rules applied uniformly to reconciliation and model events.

Audit Package

Single defensible export: chain verification, seal, event count, anomaly register, full log. CSV exports included for the journal and anomaly register.

Event Log

Append-only, SHA-256 hash-chained, persisted to localStorage. Tampering breaks the chain.

Settings

Thresholds affect matching and anomaly detection. Persisted locally.

Danger zone

Clears the event log and all snapshots from this browser.
